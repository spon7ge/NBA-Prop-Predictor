LEAKAGE AND SPLITS
==================


As-of rule
----------
A training or inference row for game G on date d may only use information
that would be knowable before tip of G:

- Prior games only for rolling / EWM / season averages (shift(1) then window).
- No same-game box score fields as features.
- Opponent / team ranks built from prior windows, not same-night stats.
- Early stopping and hyperparams never see the locked holdout.

Feature engineering lives in src/pipeline/features/. Live inference must use
the same builders (src/live_pipeline/) — train/serve skew is a second
leakage class.


Split design
------------
[ train pool: older seasons ]
        └── date-based walk-forward folds (val = next date chunk)
[ HOLD OUT: locked season — evaluate once ]

League   Train pool (current)              Holdout
------   ----------------------            --------
NBA      2021-22 → 2024-25                 2025-26
WNBA     seasons before holdout year       2026


Why split on game_date, not row index
-------------------------------------
Random or pure row-wise TimeSeriesSplit can put two players from the same
tip on opposite sides of the fold. Teammate / opponent context then leaks
across the split. Production simulation uses unique dates: every player in
a given game_date stays on the same side.

TimeSeriesSplit may still appear for quick feature / hyperparam screens;
walk-forward date folds are the reported validation story.


Holdout discipline
------------------
- Fit on train pool only; early stopping on a tail of the train pool,
  never holdout.
- If you iterate after seeing holdout metrics, that season is no longer
  clean — note it in the experiment log and preferably roll the holdout
  forward.


Checklist before trusting a number
----------------------------------
[ ] Naive / rolling features use shift-before-window
[ ] Val fold masks are date-based for the number you quote
[ ] Holdout not in eval_set
[ ] Same feature list as the joblib / live path
[ ] Starter vs bench (or minutes tier) slice reported alongside overall MAE
